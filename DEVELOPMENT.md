# Development History

## Project Genesis

**Started:** January 2025  
**Purpose:** Personal learning project to explore declarative configuration patterns and multi-protocol data orchestration

## Development Timeline

### Concept Phase
- Explored frustrations with repetitive API polling code
- Researched existing solutions (Apache Camel, Zapier, Airflow)
- Identified gap: cloud-native, YAML-configured, .NET-based framework

### Implementation Phase
- **All development:** Nights and weekends on personal time
- **All resources:** Personal computer, personal accounts
- **No employer resources used:** No company code, systems, or proprietary information

### Technology Inspiration

This project was inspired by publicly available technologies and patterns:
- **Apache Camel** - Integration framework patterns
- **Kubernetes** - Declarative YAML configuration
- **Hangfire** - Background job processing for .NET
- **Zapier/Make** - No-code automation concepts
- **AWS EventBridge** - Event-driven architecture

## Technology Choices

All technical decisions made independently for learning purposes:

- **.NET 8/10**: Modern, cross-platform framework
- **YAML**: Human-readable configuration format
- **Docker**: Cloud-native containerization
- **Redis**: Distributed state management
- **Hangfire**: Job scheduling
- **OpenTelemetry**: Observability standards
- **Hexagonal Architecture**: Clean architecture principles

Personal goals for this project:
1. Master .NET dependency injection patterns
2. Explore plugin architecture design
3. Implement multi-protocol communication (HTTP, TCP, RabbitMQ, Kafka)
4. Practice YAML schema design
5. Build production-ready cloud-native applications
6. Create useful developer tools (CLI with Cocona + Spectre.Console)
